**Rekomendasi per 22 November 2026 WIB (tanggal akses).** Uji opsi A untuk produksi iOS dan macOS. Dua engineer Kotlin dapat berbagi komponen daftar dan formulir, sementara engineer Swift paruh waktu menangani integrasi serta pengujian Apple. Pertahankan React untuk pilot internal. Pilih B untuk Apple jika PoC menunjukkan hambatan aksesibilitas atau interaksi desktop yang lebih mudah diselesaikan dengan SwiftUI.

**Rilis dan dukungan.** Versi stabil terbaru ialah Kotlin/KMP **2.4.21** dan Compose Multiplatform **1.12.2**. Kotlin **2.5.0-RC** dan Compose **1.13.0-rc01** masih prarilis. Untuk web WasmGC, minimum tanpa konfigurasi khusus ialah Chrome/Edge 119, Firefox 120, dan Safari 18.2. **Pelaksanaan bertahap**

1. Ekstrak model, validasi, klien REST, dan kontrak penyimpanan draft ke `commonMain`. Pakai API/backend yang ada. Verifikasi perilaku Android, termasuk pembacaan draft lama.
2. **A** berbagi komponen setelah audit `LocalContext`, resource, dan dependensi Android. Sesuaikan navigasi iOS serta menu dan pintasan Mac. **B** mengekspos logika KMP ke SwiftUI dan, bila berguna, ke React melalui Kotlin/JS. Kontrol native memudahkan integrasi Apple, tetapi pemeliharaan UI lebih bergantung pada kapasitas Swift. [Komponen khusus Android](https://kotlinlang.org/docs/multiplatform/compose-android-only-components.html) · [Ekspor Kotlin/JS](https://kotlinlang.org/docs/js-to-kotlin-interop.html#jsexport-annotation)
3. **Satu PoC vertikal.** Ambil daftar dari REST, buka detail, edit formulir secara luring, tutup aplikasi, pulihkan draft, lalu kirim ulang setelah koneksi pulih. Lulus jika validasi konsisten, draft utuh, server mencatat satu perubahan, dan alur dapat diselesaikan dengan VoiceOver di iOS serta keyboard di Mac. Jalankan skenario yang sama di browser pilot. Rilis Apple per alur berdasarkan hasil uji dan upaya integrasi terukur.
