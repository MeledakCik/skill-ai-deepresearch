**Fakta.** Armada menjalankan Android 10+ dan distribusi direncanakan melalui Managed Play (`MIG-WA-BRIEF` §1). Web memakai cookie sesi dan token CSRF. Hanya login browser yang terdokumentasi (`MIG-WA-REPO` §2). Pengiriman penerimaan barang memerlukan koneksi. PostgreSQL menjadi acuan stok setelah server menerima transaksi. Kontrak API tidak mendokumentasikan kunci idempotensi (`MIG-WA-API` §§1–2). Dalam sampel nonacak 40 sif, 14 laporan menyebut gangguan jaringan dan delapan menyebut pengisian ulang setelah galat. Jumlah duplikat belum terukur (`MIG-WA-OPS` §2).

**Inferensi dan keputusan.** Pertahankan web kantor. Batasi irisan pertama Android pada penerimaan barang. Pembungkus web berpotensi memakai ulang formulir, tetapi sesi dan pemindai perlu diuji pada perangkat. Klien tersendiri, baik native maupun lintas platform, memerlukan integrasi UI dan login tersendiri. Tunda pilihan framework. Kedua jalur memerlukan antrean lokal persisten serta deduplikasi server dengan ID pengiriman yang tetap saat retry.

**Usulan proof-of-concept.** Pada satu perangkat Android 10, login daring, pindai satu SKU luring, masukkan jumlah tiga, lalu hentikan proses aplikasi. Lulus jika satu entri tertunda bertahan setelah aplikasi dibuka kembali dan, saat sinkronisasi, respons yang hilang setelah commit memicu retry dengan ID sama. Hasil akhir harus tepat satu penerimaan dan stok bertambah tiga unit.

**Belum diketahui.** Verifikasi perilaku saat sesi kedaluwarsa, keamanan data lokal, rekonsiliasi dua penerimaan serentak untuk SKU yang sama, serta kesiapan akun dan peninjauan Managed Play. **Estimasi dua minggu belum didukung bukti.** Setelah uji, estimasi pekerjaan API, sinkronisasi, autentikasi, pengujian perangkat, dan distribusi. Sembilan layar hanya mengukur jumlah rute (`MIG-WA-API` §§1–3, `MIG-WA-REPO` §§1–3, `MIG-WA-OPS` §2).
