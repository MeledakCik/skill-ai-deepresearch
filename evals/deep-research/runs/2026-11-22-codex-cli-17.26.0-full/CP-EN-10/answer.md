**Decision.** Build an online console for dispatchers to view technician schedules, assign jobs and review synchronized inspections in managed Chrome and Safari. Defer native macOS until dispatchers identify a Mac-specific need. The 11-screen scope and six-week estimate are unverified. (`MIG-AW-OPS` §§1–2, `MIG-AW-BRIEF` §1)

Keep assigned jobs, inspections, photo capture and submission on Android throughout rollout. Technicians need up to 48 hours offline. Copying Room is not a viable migration path given device-bound Keystore encryption and no documented export or restore flow. Let WorkManager sync pending inspections from their devices. Read accepted inspections from the authoritative server. (`MIG-AW-APP` §§1–2, `MIG-AW-API` §2)

**Proof before estimating.** Time one dispatcher assigning one test job in each browser. Browser authentication, CORS and Safari compatibility remain unverified. Test sign-in and API access from the console origin. Force a stale `If-Match` on `PATCH`, require `409 Conflict`, then refresh, retry and verify the assignment. Replay one inspection with the same `submissionId` and require exactly one accepted record. In each browser, select a test photo, let its signed URL expire after 20 minutes, renew it and retain the image until server acknowledgement. (`MIG-AW-API` §§1–3, `MIG-AW-OPS` §2)

**Rollout gate.** Pilot only after both browsers pass. Expand when assignment time meets an agreed baseline measured on the current workflow and queued Android inspections sync without loss or duplication. On failure, disable the console and resume existing dispatch operations. (`MIG-AW-OPS` §2, `MIG-AW-BRIEF` §1)
